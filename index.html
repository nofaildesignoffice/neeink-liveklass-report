01

핵심 결론

아임웹은 ‘브랜드 홈페이지·세럼 쇼핑·상담’, 라이브클래스는 ‘온라인 강의 결제·수강’만 맡기고, 두 사이트를 같은 도메인(서브도메인)과 버튼으로 연결합니다.

아임웹에는 VOD 수강 기간·진도율·수료증 같은 강의 관리(LMS) 기능이 확인되지 않았고, 라이브클래스에는 이 기능이 모든 플랜에 기본으로 들어 있습니다. 그래서 한쪽으로 몰기보다 기능별로 나눠 쓰는 게 맞습니다.

불가같은 아이디·비밀번호 통합 로그인

아임웹 회원 API는 비밀번호를 내주지 않고, 라이브클래스는 외부 회원 연동(SSO)·회원 생성 API를 공개하지 않습니다. 대신 양쪽 모두 카카오 로그인을 켜는 것이 현실적인 방법입니다. 자세히 →

03

아임웹에서 가입하면 라이브클래스에도 같은 아이디·비밀번호로 로그인되나요?

공개된 기능으로는 안 됩니다.

회원 정보를 넘겨 같은 아이디·비밀번호로 로그인하게 하려면 ① 아임웹이 비밀번호(또는 인증)를 외부에 넘겨주거나 ② 라이브클래스가 외부 로그인 연동을 받아줘야 합니다. 두 조건 모두 공식 문서에서 확인되지 않았습니다. Codex와 Claude가 각각 조사했고 결론이 같았습니다.

왜 안 되는지 — 근거 4가지

확인 항목결과근거
아임웹 회원 API가 비밀번호를 주는가아니요회원 상세 조회 응답에는 아이디·이름·이메일·연락처·등급·그룹·소셜 ID만 있고 password·해시 항목이 없음 [S12]
아임웹이 외부 사이트용 로그인 제공자(OAuth/OIDC)가 되는가확인 안 됨아임웹의 /oauth2/authorize는 앱이 사이트 데이터에 접근하는 권한(scope: member-info:read 등)용. 회원 로그인용 ID 토큰·UserInfo 문서 없음 [S12]
라이브클래스가 외부 SSO(SAML·OIDC·JWT)를 받는가확인 안 됨로그인 수단은 이메일·비밀번호, 카카오·구글·페이스북뿐 [S1][S2]. 공개 API·웹훅 문서 없음
라이브클래스에 회원을 일괄 등록할 수 있는가확인 안 됨회원 목록 내보내기(엑셀)만 있음. 업로드·직접 생성 기능 없음 [S3]. 수강생 관리도 신청자 승인·취소·기간 변경만 가능 [S4]
“라이브클래스에서는 구글, 카카오, 페이스북의 소셜 로그인을 제공하며…”라이브클래스 운영 가이드 · 도메인 연결하기 [S2]
“오른쪽 위 [내보내기]로 회원 목록을 엑셀 파일로 내려받을 수 있어요.”라이브클래스 운영 가이드 · 사이트 회원 관리하기 [S3]

참고: 운영자가 고객 비밀번호를 받아 대신 가입시키는 방식은 보안상·개인정보보호법상 쓰면 안 됩니다.

대신 이렇게 — 카카오 로그인 양쪽 적용

1. 두 사이트 모두 카카오 로그인

아임웹은 카카오·네이버·구글·애플·페이스북·LINE을, 라이브클래스는 카카오·구글·페이스북을 지원합니다. 공통 분모인 카카오를 대표 로그인으로 둡니다. 고객은 비밀번호 없이 버튼 한 번으로 로그인합니다.

2. 단, 계정은 두 개가 생깁니다

같은 카카오 계정이어도 아임웹과 라이브클래스에 회원이 각각 만들어지고, 처음에는 카카오 동의 화면이 사이트마다 한 번씩 나옵니다. 탈퇴·정보 수정도 각각 해야 합니다 [S14].

3. 고객에게 미리 알립니다

강의 구매 버튼 근처에 “온라인 강의실은 별도 사이트(class.니잉)에서 진행돼요. 카카오로 1초 만에 시작하세요” 같은 안내를 둡니다. 헷갈림이 줄어 문의도 줄어듭니다.

커스텀 도메인을 연결하면 라이브클래스용 카카오 앱을 니잉이 직접 만들고 JavaScript 키를 라이브클래스에 전달해야 합니다 [S5]. 아임웹도 “앱과 사이트는 1:1 등록이 원칙”이라 카카오 앱을 따로 둡니다 [S13]. 하나의 카카오 앱을 두 플랫폼이 함께 쓰는 구성은 공식 지원이 확인되지 않아 권장하지 않습니다.

꼭 통합해야 한다면 — 라이브클래스에 서면 문의할 것

  • 엔터프라이즈 계약에서 SAML 2.0 / OIDC / JWT 자동 로그인 연동을 제공하는지, 비용은 얼마인지
  • 외부 회원 생성·수정·탈퇴 API, 회원가입·구매 웹훅을 제공하는지
  • 이메일 목록으로 계정을 미리 만들거나 수강 초대를 보내는 기능이 있는지
  • 아임웹과 연동한 구축 사례가 있는지

회원 정보를 아임웹에서 라이브클래스로 옮긴다면, 계약 구조에 따라 제3자 제공 동의(개인정보 보호법 제17조) 또는 처리위탁 문서·공개(제26조)가 필요합니다. 최종 판단은 개인정보 전문가 검토를 권합니다 [S20][S21].

06

고객 동선 — 온라인 클래스 구매

  1. 광고·인스타 → 아임웹 클래스 상세링크에 UTM(utm_source, utm_campaign)을 붙여 유입 경로를 남깁니다.
  2. [수강 신청하기] 버튼 → 라이브클래스 상품 페이지아임웹 회원가입을 요구하지 않습니다. 버튼은 해당 상품 페이지로 바로 연결하고 UTM을 그대로 넘깁니다.
  3. 카카오로 시작하기 → 결제라이브클래스에서 가입과 결제를 한 번에 진행합니다. 결제 전에 환불 규정을 보여줍니다.
  4. 강의실 입장 · 알림톡 안내결제 완료 알림톡에 강의실 링크와 수강 기간을 넣습니다.
  5. 수료 → 아임웹으로 재방문라이브클래스 메뉴에 ‘니잉 홈’·‘세럼 구매’·‘오프라인 클래스 상담’ 링크를 둬서 다음 구매로 이어지게 합니다.

www와 class가 같은 루트 도메인을 쓰면 GA4는 하위 도메인 사이에서 같은 방문자로 측정합니다. 결제 완료(purchase) 이벤트가 라이브클래스에서 실제로 수집되는지는 테스트 결제로 확인해야 합니다.

07

병행 운영 리스크 TOP 5와 해결책

01

수강기간 제한 — 100일·6개월 상품

Codex 조사에서 라이브클래스 구 운영 체크리스트의 “결제 대행사와의 계약 조건에 따라, 유료 클래스의 수강 기간은 최대 3개월까지만 제공이 가능합니다.” 문구가 확인됐습니다. 해당 구 가이드 주소는 현재 새 가이드 홈으로 이동되고, 현행 가이드에서는 이 문구가 보이지 않습니다. 현행 가이드에는 수강생별 기간 연장(1회 최대 1,000일) 기능이 있습니다.

해결 — 계약 전 라이브클래스 채팅으로 “유료 상품 수강기간 100일·180일 설정이 가능한지” 서면으로 받습니다. 안 되면 90일 과정 + 수료 후 연장, 또는 정기결제(구독)형으로 바꿉니다.

02

회원 이중 가입

아임웹과 라이브클래스는 회원 DB가 따로입니다. 통합 로그인이 안 되므로(03 참고), 고객이 “가입했는데 왜 또 가입하냐”고 느낄 수 있습니다.

해결 — 강의 구매에는 아임웹 가입을 요구하지 않고, 양쪽에 카카오 로그인을 켭니다. 구매 버튼 옆에 “강의실은 별도 사이트” 안내 문구를 둡니다.

03

결제·환불·고객 정보 분산

세럼 주문은 아임웹, 강의 결제는 라이브클래스에 쌓입니다. 라이브클래스는 기본 환불 규정이 없어서 규정을 써두지 않으면 요청대로 환불해야 할 수 있습니다 [S11].

해결 — 상품별 결제 위치를 고정하고(02 표), 라이브클래스 상품 페이지·공지에 온라인 강의 환불 규정을 따로 게시합니다. CS 응대용으로 월 1회 양쪽 회원 목록을 내보내 대조합니다.

04

광고 전환 추적 끊김

광고는 아임웹으로 들어오고 결제는 라이브클래스에서 일어나 광고 성과가 누락될 수 있습니다.

해결 — 같은 GA4 측정 ID와 Meta 픽셀을 두 사이트에 모두 설치하고, 버튼 링크에 UTM을 유지합니다. 오픈 전 실제 결제로 이벤트 수집을 확인합니다.

05

브랜드·문의 창구 분산

주소·디자인·문의 채널이 달라지면 고객이 다른 회사 사이트로 오해할 수 있습니다.

해결 — class 서브도메인, 같은 로고·색상·푸터를 씁니다. 라이브클래스 톡상담도 니잉 카카오톡 채널과 연결해 문의 창구를 하나로 둡니다. 결제창·카드 명세서에 표시되는 상호는 오픈 전 확인합니다 [확인 필요].

08

구축 체크리스트

계약 전

  • 라이브클래스에 수강기간 100일·180일 설정 가능 여부 서면 확인
  • 통합 로그인이 꼭 필요하면 엔터프라이즈 SSO·API 제공 여부와 비용 문의
  • 결제창·카드 명세서 표시 상호 확인
  • 강의 총 분량·영상 용량으로 플랜 결정 (권장 시작: 마이크로, 연 결제 시 20% 할인)

도메인·로그인

  • 유료 플랜 구독 후 채팅으로 class.니잉도메인 연결 요청 → DNS 입력 → 내부 작업 영업일 2~5일 사업자등록 정보가 필요할 수 있음 [S2]
  • 라이브클래스용 카카오 앱 생성 → 도메인·sso.liveklass.com·콜백 주소 등록 → JavaScript 키 전달 [S5]
  • 구글·페이스북 로그인도 쓸 경우 각각 같은 방식으로 연동 (안 하면 기존 소셜 계정 로그인 불가) [S2]
  • 아임웹 카카오 로그인 설정 (별도 앱) [S13]

연결·추적

  • 아임웹 GNB ‘온라인 클래스’, 각 상세 페이지 구매 버튼 → 라이브클래스 상품 URL + UTM
  • 라이브클래스 메뉴 → 니잉 홈·세럼·오프라인 상담 링크
  • 두 사이트에 같은 GA4 측정 ID, Meta 픽셀 설치 (라이브클래스 GTM은 1:1 상담으로 설치 요청) [S22]
  • 테스트 결제로 GA4 purchase·픽셀 이벤트 확인 후 환불 처리

법적 고지·운영

  • 라이브클래스 푸터에 상호·대표·사업자번호·통신판매업 신고번호 입력 니잉 통신판매업 신고번호 [클라이언트 확인 필요]
  • 온라인 강의 환불 규정 작성·게시 (전자상거래법 제17조, 콘텐츠이용자보호지침 등 참고) [S11]
  • 개인정보 처리방침에 라이브클래스 이용 사실(수탁자·위탁업무) 반영
  • 원격 교육 형태가 학원·평생교육시설 신고 대상인지 확인 [S26]
  • 알림톡용 비즈니스 인증 카카오 채널 연결, 결제 완료·수강 리마인드 템플릿 검수 (최대 영업일 7일) [S10]
  • 판매 시작 전 가격·할인·패키지 구성 확정 공개 후에는 판매 조건 가격과 할인을 바꿀 수 없음 [S15]

09

출처로 확인하지 못한 항목

아래는 공개 문서로 확인하지 못해 단정하지 않은 내용입니다. 라이브클래스·아임웹 고객센터 답변으로 채워야 합니다.

  • 라이브클래스 유료 상품 수강기간 상한 (구 가이드 ‘최대 3개월’ 문구의 현재 유효 여부)
  • 라이브클래스 SAML·OIDC·JWT SSO, 회원 생성 API, 웹훅, 회원 일괄 등록 (엔터프라이즈 포함)
  • 라이브클래스 네이버·애플 로그인 지원
  • 라이브클래스 통합 계정이 다른 라이브클래스 사이트에서 추가 절차 없이 로그인되는지
  • 카카오 앱 하나를 아임웹·라이브클래스가 함께 쓰는 구성의 공식 지원
  • 아임웹 회원가입 웹훅 이벤트, 외부 서비스용 회원 로그인(OIDC) 제공
  • 패키지 판매 시 수강신청 건수 차감 방식(1건 vs 포함 상품 수)
  • 결제창·카드 명세서 표시 상호
  • 아임웹과 라이브클래스 공식 연동 상품·구축 사례
